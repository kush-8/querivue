## Prepared datasets

Prepare one immutable DuckDB database file per Dataset. The file contains all tables imported from that upload. CSV, TSV, flat JSON, JSON Lines, and Parquet each produce one table. Excel can produce multiple worksheet tables. Show worksheet names and let the user select worksheets before ingestion, with all non-empty visible worksheets selected by default. Show hidden worksheets with a Hidden label and leave them unselected unless the user explicitly includes them. SQLite contributes the selected tables. For each selected worksheet, propose a header row and show a small preview. Let the user confirm or change the header row before table ingestion. Import one rectangular table per selected worksheet. When a worksheet contains multiple tables, ask the user to select the cell range for the table to import in the preview. For a worksheet containing one table, infer its range without requiring range selection. Allow merged titles outside the imported table. If a merged range intersects the imported header or data, flag its location and require the user to fix the worksheet before importing that table. For formulas in the selected table, import their saved results. If a formula has no saved result or contains an Excel error, show its cell location and require recalculation and saving of the workbook before importing that table. Explain in the preview that saved formula results are used and can be stale. The formula importer library and multi-table detection rules remain open. Store the prepared file on the shared persistent volume and record its reference and metadata in Postgres. A replacement upload receives a new Dataset ID and prepared database. Generate unique SQL column names for blank or duplicate headers. Preserve original header labels and source column positions in the catalog, and show the mapping in the import preview. The minimum table catalog records a stable table ID and SQL name, the source worksheet and selected range or SQLite table where applicable, original column labels, SQL column names, source positions, confirmed types, row count, per-column null counts, and import warnings. Exact catalog field types and table naming rules remain open. Show inferred column types in the import preview and allow users to override them. Validate proposed types against the complete selected table before publishing the Dataset. Mark a Dataset ready only after every selected table passes validation and preparation succeeds. If any selected table fails, keep the Dataset unavailable for analysis. Let the user fix the issue or deselect the affected table and resubmit before publication. Retain failed staged uploads until the user retries or deletes them. Allow retry with revised import settings using the stored upload, and count its raw bytes toward the project upload limit while retained. Build and validate the prepared DuckDB database inside the sandbox, transfer the completed file to temporary persistent storage, verify the transfer, and place it at its final immutable path. Save the catalog and file reference before marking the Dataset ready. A crash before readiness leaves it unavailable for analysis. Recovery can verify the saved file and finish publication or rebuild it. Associate each ingestion attempt with the confirmed import settings and allow only the current attempt to publish. Repeated delivery after successful publication returns the existing result. A late attempt cannot overwrite or invalidate newer preparation. Delete temporary files belonging to failed or superseded ingestion attempts once those attempts are confirmed inactive. Retain the staged upload for retry under its agreed retention rule, and retain the published DuckDB snapshot until Dataset deletion. Exact attempt identity, detailed publication mechanics, inactive-attempt detection, and cleanup timing remain open. For mixed or ambiguous values, show a warning and propose a conservative type that preserves the source values, including meaningful leading zeros in identifiers. If a selected type conversion fails, block import of the affected table and show the failure count and sample source locations. The user can choose a compatible type or correct the source. Preserve native date types from Excel and Parquet, and infer unambiguous text dates. Flag ambiguous date columns in the preview and require the user to confirm the format before importing them as dates. Apply the confirmed format consistently across the column, validate every value, and save it with the import settings for reproducible retries. Configure date formats and source timezones per column. Show detected values in the import preview, let the user confirm or change them, and save the confirmed choices with the import settings. Preserve date-only values as dates. Keep timestamps without timezone information unspecified unless the user supplies a timezone. Normalize timestamps with explicit offsets to UTC and preserve supplied source timezone information. Ask for the analysis timezone when it could change calendar grouping. Invalid dates follow the agreed conversion-failure rule. Preserve native nulls as SQL NULL. Keep literal text such as NA, NULL, and unknown unchanged unless the user explicitly marks it as missing. Let users configure missing-value markers per column in the import preview and save those choices with the import settings. For CSV and TSV, import empty unquoted fields as SQL NULL, preserve quoted empty strings as empty strings, and preserve whitespace-only text. Match user-configured missing-value markers exactly and case-sensitively. Verify parser support for preserving quoted empty strings. Timezone storage mappings, mixed-timezone handling, remaining inference and conversion rules, error display limits, normalization and collision rules, table naming, catalog schema, sandbox staging, and connection security remain to be designed.

### Accepted format-specific import rules

- CSV supports UTF-8 with an optional BOM. Detect its delimiter and show it in the import preview for correction. TSV uses tabs. Invalid encoding produces an actionable error.
- Expose decimal and thousands separators when needed. Require confirmation for ambiguous numeric text. Currency symbols and percentage strings require an explicit conversion choice.
- Block the affected table on malformed CSV rows, invalid JSON records, or unsupported values, and report source locations. Preserve valid source rows during import.
- For SQLite, import selected ordinary stored tables. Exclude views, virtual tables, triggers, and executable schema behavior from the prepared database.
- For Excel, prefer declared table ranges. Otherwise propose a detected rectangular range in the preview. Multiple tables trigger the agreed range selector. Layouts that cannot be interpreted reliably produce a clear validation error.
