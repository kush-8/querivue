## Prepared datasets

Prepare one immutable DuckDB database file per Dataset. The file contains all tables imported from that upload. CSV, TSV, flat JSON, JSON Lines, and Parquet each produce one table. Excel can produce multiple worksheet tables. Show worksheet names and let the user select worksheets before ingestion, with all non-empty visible worksheets selected by default. Show hidden worksheets with a Hidden label and leave them unselected unless the user explicitly includes them. SQLite contributes the selected tables. For each selected worksheet, propose a header row and show a small preview. Let the user confirm or change the header row before table ingestion. Import one rectangular table per selected worksheet. When a worksheet contains multiple tables, ask the user to select the cell range for the table to import in the preview. For a worksheet containing one table, infer its range without requiring range selection. Allow merged titles outside the imported table. If a merged range intersects the imported header or data, flag its location and require the user to fix the worksheet before importing that table. For formulas in the selected table, import their saved results. If a formula has no saved result or contains an Excel error, show its cell location and require recalculation and saving of the workbook before importing that table. Explain in the preview that saved formula results are used and can be stale. The formula importer library and multi-table detection rules remain open. Store the prepared file on the shared persistent volume and record its reference and metadata in Postgres. A replacement upload receives a new Dataset ID and prepared database. Generate unique SQL column names for blank or duplicate headers. Preserve original header labels and source column positions in the catalog, and show the mapping in the import preview. The minimum table catalog records a stable table ID and SQL name, the source worksheet and selected range or SQLite table where applicable, original column labels, SQL column names, source positions, confirmed types, row count, per-column null counts, and import warnings. Exact catalog field types and table naming rules remain open. Show inferred column types in the import preview and allow users to override them. Validate proposed types against the complete selected table before publishing the Dataset. Mark a Dataset ready only after every selected table passes validation and preparation succeeds. If any selected table fails, keep the Dataset unavailable for analysis. Let the user fix the issue or deselect the affected table and resubmit before publication. Retain failed staged uploads until the user retries or deletes them. Allow retry with revised import settings using the stored upload, and count its raw bytes toward the project upload limit while retained. Build and validate the prepared DuckDB database inside the sandbox, transfer the completed file to temporary persistent storage, verify the transfer, and place it at its final immutable path. Save the catalog and file reference before marking the Dataset ready. A crash before readiness leaves it unavailable for analysis. Recovery can verify the saved file and finish publication or rebuild it. Associate each ingestion attempt with the confirmed import settings and allow only the current attempt to publish. Repeated delivery after successful publication returns the existing result. A late attempt cannot overwrite or invalidate newer preparation. Delete temporary files belonging to failed or superseded ingestion attempts once those attempts are confirmed inactive. Retain the staged upload for retry under its agreed retention rule, and retain the published DuckDB snapshot until Dataset deletion. Exact attempt identity, detailed publication mechanics, inactive-attempt detection, and cleanup timing remain open. For mixed or ambiguous values, show a warning and propose a conservative type that preserves the source values, including meaningful leading zeros in identifiers. If a selected type conversion fails, block import of the affected table and show the failure count and sample source locations. The user can choose a compatible type or correct the source. Preserve native date types from Excel and Parquet, and infer unambiguous text dates. Flag ambiguous date columns in the preview and require the user to confirm the format before importing them as dates. Apply the confirmed format consistently across the column, validate every value, and save it with the import settings for reproducible retries. Configure date formats and source timezones per column. Show detected values in the import preview, let the user confirm or change them, and save the confirmed choices with the import settings. Preserve date-only values as dates. Keep timestamps without timezone information unspecified unless the user supplies a timezone. Normalize timestamps with explicit offsets to UTC and preserve supplied source timezone information. Ask for the analysis timezone when it could change calendar grouping. Invalid dates follow the agreed conversion-failure rule. Preserve native nulls as SQL NULL. Keep literal text such as NA, NULL, and unknown unchanged unless the user explicitly marks it as missing. Let users configure missing-value markers per column in the import preview and save those choices with the import settings. For CSV and TSV, import empty unquoted fields as SQL NULL, preserve quoted empty strings as empty strings, and preserve whitespace-only text. Match user-configured missing-value markers exactly and case-sensitively. Verify parser support for preserving quoted empty strings. Timezone storage mappings, mixed-timezone handling, remaining inference and conversion rules, error display limits, normalization and collision rules, table naming, catalog schema, sandbox staging, and connection security remain to be designed.

### Accepted format-specific import rules

- CSV supports UTF-8 with an optional BOM. Detect its delimiter and show it in the import preview for correction. TSV uses tabs. Invalid encoding produces an actionable error.
- Expose decimal and thousands separators when needed. Require confirmation for ambiguous numeric text. Currency symbols and percentage strings require an explicit conversion choice.
- Block the affected table on malformed CSV rows, invalid JSON records, or unsupported values, and report source locations. Preserve valid source rows during import.
- For SQLite, import selected ordinary stored tables. Exclude views, virtual tables, triggers, and executable schema behavior from the prepared database.
- For Excel, prefer declared table ranges. Otherwise propose a detected rectangular range in the preview. Multiple tables trigger the agreed range selector. Layouts that cannot be interpreted reliably produce a clear validation error.

## Ingestion integration contract

Prepared 18–19 November 2026; **design approved 20 November 2026**. Earlier approved format/user-confirmation rules remain binding. This section resolves their agent-facing representation. Numerical settings and library choices are accepted development candidates subject to the stated build/measurement gates; design approval does not authorize code, dependency installation or live runs. See the [phase closure](../memory.md#final-agent-architecture-phase-closure--20-november-2026).

### Dataset, catalog and import settings

Use the shared versioned canonical envelope/UUID policy. Dataset identity is one immutable upload snapshot; raw upload SHA-256, byte size, detected format and opaque storage reference are runtime metadata. Never use a filename/path as authority. Store metadata in the same standalone SQLite authority as runs; move that authority together to Postgres later. The prepared database and catalog are immutable artifacts outside sandbox lifetimes.

| Record | Required typed fields and relationships |
| --- | --- |
| ImportSettings | settings_version; source_format; ordered selected source-table/worksheet/range descriptors; header row/presence; confirmed delimiter/encoding/quote/escape for CSV/TSV; per-column requested type, exact missing markers, decimal/thousands separators, date/time format/source timezone and explicit conversion choice. Preserve original labels and user confirmation identity; hash canonical settings. |
| PreparationAttempt | dataset_id, attempt_id UUID, monotonically increasing attempt_number, settings_hash, upload_hash, expected owner_generation, phase, environment/profile identity, physical incarnation/retirement state, limits/deadline, diagnostic_ref and candidate/publication refs. One active attempt pointer per Dataset. |
| PreparedSnapshot | dataset_id, attempt_id, snapshot_id UUID, catalog_id/hash, ordered table_ids, immutable DuckDB artifact reference/size/SHA-256, schema_fingerprint, preparation environment/format/settings identities, dependencies and committed ready revision. |
| TableCatalog | table_id UUID, dataset_id/snapshot_id, ordinal, generated sql_name, original source descriptor, row_count integer ≥0, ordered columns, warnings and profile evidence refs. Source descriptor is worksheet name plus selected A1 rectangle/header row, SQLite table name, or single-file format; this text is untrusted metadata. |
| ColumnCatalog | zero-based ordinal/source position, runtime column_id UUID, original_label or null, sql_name, exact supported DuckDB type, nullable, null_count, confirmed conversion/date/timezone/missing/numeric settings, and timezone-provenance ref where needed. Source cell/line references stay separate from evidence artifact locators. |

Imported names are presentation/SQL bindings, not authority. Use table names `t_001`, `t_002`, … in confirmed selection order within a Dataset. Runtime attaches each Dataset read-only under `d_` plus its validated UUID hex, so table names cannot collide across Datasets. Models get qualified aliases/table IDs and quoted SQL identifiers, never storage paths.

For columns, preserve the original label exactly. Generate an ASCII SQL base by NFKC-normalizing a separate copy, lowercasing, replacing non-ASCII letters/digits/underscore runs with `_`, trimming underscores, using `column_<1-based position>` when empty and prefixing `c_` for an initial digit. Limit generated names to 63 characters, truncating before a collision suffix. Reserve natural base names first, then assign the first occurrence its base and subsequent collisions the smallest unused `_2`, `_3`, … in source order. Example: `a, a, a_2` becomes `a, a_3, a_2`. Always quote identifiers; normalization never changes stored cell text. Artifact result naming still uses the specialist's existing mapping contract.

### Parsing, typing and conversion

Propose DuckDB's pinned native CSV/TSV/JSON/Parquet readers where they satisfy the contract, Arrow for typed transfer, openpyxl plus defusedxml for .xlsx metadata/cached values, and Python's sqlite3 for isolated SQLite inspection/copy. No extension auto-install/network fetch, spreadsheet recalculation, macros, formulas, SQLite triggers/views/virtual tables or user-supplied executable parsing code. Use the same DuckDB build for preparation and analysis. Dependencies must be pinned in the built manifest and verified; these library choices are proposals, not compatibility claims.

CSV/TSV inspection may use a bounded preview to propose settings, but publication validates every selected row with explicit confirmed schema/dialect. Strict malformed-row errors never enable ignore_errors, null padding, row skipping, lossy casts or hidden sampling. Preserve quoted empty text versus unquoted empty NULL; candidate DuckDB `allow_quoted_nulls=false` plus explicit empty null marker needs a parser fixture before acceptance. Apply custom missing markers per column, exactly/case-sensitively after obtaining the logical field text; preserve quoted empty strings unless the user explicitly marks empty text missing. Whitespace and literal NA/NULL stay text by default. Detect an unsupported dialect rather than change its meaning.

Inference is deterministic and conservative: native booleans/finite numbers/date types retain compatible supported types; unambiguous integral text without meaningful leading zeros may propose int64/uint64; exact decimal text may propose DECIMAL(p,s) ≤38; explicitly formatted dates/times use their confirmed formats. Ambiguous/mixed text or unsupported exact numeric precision defaults to VARCHAR with a warning and original logical text, not float rounding. All-null columns propose nullable VARCHAR unless confirmed otherwise. Preserve original lexical numeric values for text fallback; SQL type range/precision checks use the shared TypedScalar policy. Unsupported nested/complex/binary types require an explicit supported conversion or fail the selected table; never coerce them to null. Non-finite numerical values are rejected or require an explicit user-confirmed text representation.

JSON is a top-level array of flat objects; JSONL is one flat object per nonblank line. Reject duplicate object keys and nested arrays/objects as values. Form the column union in first-seen key order; absent keys become NULL. Parse integer/decimal literals without binary float loss; mixed scalar columns use the same confirmed conservative typing rules. A valid empty table with known columns is supported; no records and no discoverable/confirmed schema yields an actionable missing-schema failure. Preserve quoted strings and meaningful leading zeros. Parquet's supported native schema is authoritative; incompatible types require explicit conversion, not guessed JSON serialization.

For .xlsx, compare formula and cached-value views of the immutable workbook and import saved results only. Reject formulas with no cached result and cached Excel errors with cell locations; never run Excel/LibreOffice or fetch external links. Use `keep_links=false`, do not preserve/execute VBA, and harden ZIP/XML parsing before library access. Prefer declared ranges; otherwise propose a header and rectangle from bounded occupied-cell scans. Blank-row/column-separated regions or multiple declared tables trigger explicit range selection; no heuristic claims to recognize every multi-table layout. The user confirms the preview/range/header; merged-cell and ambiguous-layout failures follow existing rules. Validate full selected ranges, including internal blank rows; trimming is limited to the confirmed outer range. Honor workbook date epoch; unsupported/fictitious dates fail rather than silently shift.

For SQLite, validate file signature and database consistency in the ingestion sandbox. Open the uploaded copy read-only with extension loading disabled, trusted schema disabled where supported, a restrictive authorizer and deadline/progress cancellation. Enumerate only ordinary user tables; exclude sqlite internal/shadow/virtual tables, views and generated/executable schema features. Quote runtime-validated selected identifiers, never execute uploaded schema text or attach the upload to an analytical connection. Copy selected stored scalar values into newly created trusted DuckDB tables. A file needing missing journal/WAL content or failing consistency cannot publish. Type-check actual values, not just declared SQLite affinity.

### Temporal identity and provenance

Date stays DATE; time stays TIME; timezone-free timestamp stays TIMESTAMP with microseconds. Explicit-offset/source-zone timestamps become UTC TIMESTAMPTZ after validated conversion. Preserve confirmed source zone/format and, for mixed offsets, per-row original offset/zone provenance in a separate governed artifact linked from ColumnCatalog. Do not invent visible data columns or discard different offsets. Reject sub-microsecond values unless an explicit conversion policy is confirmed; no silent rounding. Ambiguous/nonexistent DST local times require explicit source correction or disambiguation before publication. Unknown/mixed zone meaning is not guessed. The SQL session uses confirmed analysis timezone, otherwise UTC; consequential missing analysis timezone still requires analytical clarification. Canonical input hashing preserves exact supplied typed representations; prepared normalized UTC values have their own recorded conversion lineage.

### Typed profiles and Direct-answer grounding

Build exact row counts, null counts, supported date/time min/max and bounded candidate-key records during complete-table validation. Keep source_schema key hints distinct from verified_unique_non_null checks; a declared SQLite constraint is not proof of actual imported cardinality. No extra automatic numeric aggregates/top categories/histograms or model profiling pass. Additional requested statistics use SQL.

Publish an immutable typed Parquet profile evidence artifact for each table: one table-summary row (`row_count`) and ordered column-profile rows with column ID/ordinal, `null_count`, eligible typed temporal bounds and key-basis/verification fields. Use separate typed bound columns/discriminators for date versus timestamp versus timestamptz, not an untyped JSON string. Required schema/coverage/physical row/column locators and producer provenance are the shared evidence contract; producer kind is ingestion_profile, with settings/environment/snapshot identity rather than fabricated executed SQL. Dependencies include the owning Dataset snapshot. A runtime registration transaction commits profile evidence with the snapshot/catalog; it is ineligible before ready.

Runtime can supply actual complete typed profile cells to Supervisor/SQL packets. Direct value spans may cite only those supplied eligible cells/metadata. It cannot calculate a non-null count by subtracting null_count from row_count or infer key uniqueness from a source hint; obtain a computed quantity when requested. Profile absence/corruption blocks that profile-backed route, never invents a JSON-path citation. Models never see the full upload by gaining a profile reference.

### Preparation lifecycle, replacement and cleanup

Public Dataset states remain processing/ready/failed; internal phases are staged → inspecting → awaiting_confirmation → preparing → validated → transferred → ready, with failed/invalidated/deleted outcomes. Record current settings/attempt and reserve resource/time budget before dispatch. Waiting for user confirmation releases the ingestion sandbox; it does not carry Python variables forward. A settings change after work starts allocates a new attempt and fences the old one. Duplicate delivery under the same invocation/attempt/settings hash restores recorded progress; changed content under an existing identity fails integrity validation.

Build a complete candidate snapshot/catalog/profiles in quarantine, close/checkpoint the DuckDB file so no unpublished WAL is required, reopen read-only, validate counts/schema/profile locators, hash and transfer all immutable bytes, then verify persistent copies. One guarded ledger transaction checks Dataset/current attempt/generation, upload/settings identities, live source/deletion state and complete artifact availability, commits all metadata/evidence and marks ready. No partially prepared selected-table subset is visible. Lost acknowledgment reads that same ready record; a crash before commit cannot expose a candidate. Recover trusted validated bytes after rechecking guards, otherwise rebuild only after prior execution is reconciled/retired.

Deleting a staged/prepared Dataset immediately denies access and fences attempt publication; cleanup follows confirmed process retirement and reference checks. Delete superseded/failed temporary outputs only after the owning incarnation is confirmed inactive; retain failed staged uploads for user retry/deletion and count them toward the 50 MiB Project raw-upload cap. Dataset/settings retries do not silently create duplicate raw-upload charges. Successful replacement atomically makes the new Dataset ready and tombstones/invalidates the old Dataset under the same authority; failed replacement leaves the original usable. Replacement needs capacity for both raw uploads until success, unless the user deletes the original first. Separate add keeps both identities. Do not delete retained completed outputs by a TTL contrary to user deletion policy.

### Acceptance and remaining evidence

Fixtures cover every accepted format, column collision mapping, quoted empty/null/whitespace, malformed input/duplicate JSON keys/nesting, exact integer/decimal/date/offset values, mixed SQLite types and forbidden schema, XLSX cached formulas/errors/merges/multiple regions, full-table conversion failures beyond preview, empty/all-null data, profile typed locators and forbidden Direct arithmetic, failed/successful replacement, competing attempts, crashes at every publication boundary and deletion/cleanup races. Error counts describe the full validated scope and explicitly mark early resource termination; bounded sample locations never imply only those rows failed. Sandbox finite caps are in the proposed final-phase execution profile. Exact built library versions, parser fidelity, environment compatibility and actual enforcement remain implementation/evaluation gates.

The approved [environment/admission/lifecycle contract](sandbox-execution.md#environment-admission-and-lifecycle-contract) owns environment manifests, finite resource caps, transfer quarantine, process retirement and controller cleanup. PreparationAttempt and PreparedSnapshot reference that immutable environment manifest rather than independent version strings. The raw-upload cap, expanded-input cap and retained prepared/evidence storage ceiling are separate admission checks. Inspection defaults never authorize a lossy conversion; full-range validation and all-selected-table atomic readiness remain mandatory.

Profile schema proposal: `profile_schema_version`, `table_id`, `snapshot_id`, `row_kind` (table_summary/column_profile), nullable `column_id`/`column_ordinal`, nullable nonnegative int64 `row_count`/`null_count`, `bound_kind` (none/date/time/timestamp/timestamptz), corresponding nullable native typed lower/upper columns, nullable `source_key_hint` boolean and `key_check` (not_checked/verified_unique_non_null/not_unique_or_null). Exactly one summary precedes one row per ordered catalog column; only summary has row_count, only column rows have column identity/null_count/key fields, and only the matching bound columns may be populated. Unknown/nonapplicable bounds stay null with bound_kind=none, never zero. Exact physical schema and locator policy are versioned together. Unsupported row counts outside int64 fail rather than overflow.

Candidate-key verification covers single columns only: at most eight column ordinals, prioritizing source key hints then confirmed key-check selections in source order. Each source hint and verification result has its own field; composite source constraints remain catalog metadata and cannot imply a verified single-column key. No automatic all-column cardinality scan. An unchecked key is not_checked, distinct from a failed uniqueness/non-null test. These bounds affect profiling cost, never the completeness of imported rows.

These establish available APIs, not verified import fidelity or isolation.
