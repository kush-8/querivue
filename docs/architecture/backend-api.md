# Backend API and Chat connection

**Design approved and planning closed, 25 November 2026.** This guide owns the application HTTP/WebSocket contracts. See the [closure and remaining owners](../memory.md#backend-api-planning-closure--25-november-2026). [Database/storage](database-storage.md), [agent integration](agent-integration.md) and [ingestion](data-ingestion.md) own their existing domain contracts.

## Approved direction and implementation boundaries

The user accepted ordinary Django JSON endpoints with strict schemas, loopback-only single-operator access without login/signup, durable receipts, stable idempotency and Retry as recovery of the same interrupted run. The user explicitly replaced the proposed Chat polling connection with WebSockets for seamless streaming. Chat sends commands and receives live delivery over that socket. HTTP remains for management, uploads/downloads, initial snapshots and recovery of transport state; it is not the primary Chat update mechanism.

Use Django Channels on ASGI for the socket route, retaining ordinary Django HTTP views. Use channels_redis with the existing Redis service with separate namespaces for notifications, checkpoints and job-delivery infrastructure. Channels and its Redis adapter are selected; exact compatible package/ASGI server builds still require pinning and verification before enablement. Selection does not install dependencies or choose the worker framework. Native ASGI WebSocket handling is an alternative with fewer packages but more connection/protocol plumbing. The socket consumer never performs inference, ingestion or the long-lived agent run; it commits commands and delivers public state while application workers own execution.

Ordinary Django JSON views plus strict application DTOs were chosen over DRF for the fixed local API, avoiding a second framework/validation layer; GraphQL has no demonstrated need here. WebSockets supersede the earlier Chat polling proposal at the user's request. HTTP snapshot/status lookup remains for initialization and recovery, and server-side durable-watermark checks cover missed notifications. These choices do not weaken entry/review/publication or deletion gates.

## HTTP conventions and local boundary

Base `/api/v1/`; WebSocket `/ws/v1/projects/{project_id}/chats/{chat_id}/`. Same-origin UI proxy handles HTTP and Upgrade traffic, including local development. Bind host-facing ingress to loopback only, validate exact configured Host/origin including port, deny broad CORS, and enforce Django CSRF on unsafe HTTP methods. HTTP data requests require `X-Querivue-Client: web`; this is a browser request-shape guard, not a secret. The OS/local-process environment is trusted; this is not authentication for LAN, shared-host or hosted deployment. Public signup/account management remain outside scope.

Use snake_case JSON fields, lowercase enum labels, canonical UUID strings and strict named request/response schemas. Reject unknown fields, duplicate JSON keys, invalid Unicode and coercion of numbers/booleans/IDs. Preserve original text; size/blank validation does not normalize it. Nonblank names/titles are metadata, not identity. Operational times use UTC ISO strings; counters have their approved bounds. Analytical values use the existing lossless typed scalar forms, not browser floating-point approximations. No raw model messages, owner fences, filesystem paths, credentials, private drafts or reasoning enter public DTOs/logs.

Object responses use `{data: <typed object>, request_id: <uuid>}`; list data is `{items: [...], next_cursor: <opaque cursor|null>}`. Stable bounded pagination binds parent/filter/order and an upper-watermark snapshot, with deterministic ID tie breaks. A cursor is not authorization. Public resource objects include id, relevant parent IDs, revision, lifecycle/status and explicitly defined public links; no automatic ORM/ledger serialization. A missing and an out-of-scope identity both return 404; authorized revoked content returns 410 with a non-content reason. All content/status/ticket responses use `Cache-Control: no-store`.

Create/command HTTP calls require `Idempotency-Key`, generated once per intent. Bind operator/Project, logical operation and exact validated request digest, independent of transport: switching from socket to HTTP reconciliation cannot create another submission. A duplicate returns the same durable identity after current authorization; different content under the key returns 409 `idempotency_conflict`. Replays never return a cached copy of erased data. State edits and deletions require `If-Match` for the advertised resource revision; missing is 428 and a genuine stale precondition is 412. Resolve a duplicate's original committed operation before rejecting its now-stale precondition. GET/HEAD never start work or consume analytical budgets.

Return 201 for immediate creation and 202 plus Location for durably accepted asynchronous commands. Acceptance is not entry approval or successful execution. A crash/timeout with unknown commit outcome is resolved by the original key/status resource, not a newly generated request. Errors use `{error: {code, message, field_errors, retryable}, request_id}` with bounded sanitized messages. Map malformed/unknown schema input to 400; disallowed local request/origin/CSRF to 403; missing scope to 404; revoked to 410; state/identity conflicts to 409; too large to 413; unsupported media to 415; finite admission limits to 429; dependency temporarily unavailable to 503; integrity/server failure to 500. HTTP Retry-After is advisory and never authorizes an analytical retry or extends a deadline.

## Management and data endpoints

The table defines request/response schema responsibilities by their field sets. Every command also uses the idempotency/precondition rules above. Bodies marked empty reject extra fields. Format-specific selection/conversion fields reuse the approved ingestion user-settings schema; immutable settings/attempt/environment identities are server-created, never client-authoritative.

| Method and path under `/api/v1` | Input and public result |
| --- | --- |
| GET `/client-context/` | No body; returns protocol_version, masked csrf_token, public configured capabilities/limits and local connection policy. Sets required CSRF cookie; no Project content or credentials. This route still requires the application header. |
| GET / POST `/projects/` | List via cursor; create `{name}` → Project `{id,name,revision,lifecycle,raw_bytes_used,raw_bytes_reserved,raw_bytes_limit}`. |
| GET / PATCH / DELETE `/projects/{p}/` | Read Project; rename `{name}` with revision; delete empty body → DeletionReceipt. Revocation is immediate even when cleanup remains pending. |
| GET / POST `/projects/{p}/chats/` | List Chat; create `{title}` → Chat `{id,project_id,title,revision,lifecycle}`. |
| GET / PATCH / DELETE `/projects/{p}/chats/{c}/` | Read/rename `{title}`/delete; same ownership/revision rules. Chat removal preserves Project Datasets. |
| GET `/projects/{p}/chats/{c}/snapshot/` | Cursor/page limit; returns committed visible items, active submission/run/card summaries, semantic visibility cutoff and delivery cursor. No unapproved candidate content. |
| POST `/projects/{p}/chats/{c}/connection-tickets/` | Empty body, CSRF protected → single-use ticket, expires_at and bound socket path. Not an operator login or persistent access token. |
| POST `/projects/{p}/uploads/` | `{filename,size_bytes,sha256}` → Upload `{id,revision,state,declared_size_bytes,received_size_bytes,content_url}` after raw quota reservation. No file bytes in JSON. |
| PUT `/projects/{p}/uploads/{u}/content/` | Complete binary body, declared length/digest and stable upload intent → same Upload. Initial version uses whole-file transfers, not resumable chunks. Verify stream limits/hash; retry lost acknowledgment by querying Upload before retransferring. Concurrent content writers conflict; a completed identical upload is recognized without republishing bytes. |
| GET / DELETE `/projects/{p}/uploads/{u}/` | Read upload state; delete unowned/unadmitted upload with revision. A Dataset-owned upload must be removed through that Dataset's lifecycle rather than bypassing it. |
| POST `/projects/{p}/ingestions/` | `{upload_id,replaces_dataset_id:null|uuid}` → entry SubmissionReceipt, nullable dataset_id until ingestion admission. Raw bytes stay out of semantic model requests. Replacement names the original explicitly. |
| GET `/projects/{p}/datasets/` and GET `/projects/{p}/datasets/{d}/` | List/read Dataset `{id,project_id,revision,status,preparation_phase,current_attempt,preview_ref,snapshot_ref,failure,replaces_dataset_id}` with nullable refs. Only committed ready snapshots are eligible sources. |
| GET `/projects/{p}/datasets/{d}/import-preview/` | Read exact preview identity/hash, settings revision, proposed tables/columns/ranges/conversions/warnings and confirmation requirements. Raw samples are bounded and untrusted display data. |
| POST `/projects/{p}/datasets/{d}/preparations/` | `{preview_id,preview_hash,settings_revision,confirmed_settings}` → preparation receipt. Settings changes create/fence attempts under the approved ingestion rules; no in-place snapshot mutation. Retry preserves the raw upload charge. |
| DELETE `/projects/{p}/datasets/{d}/` | Empty body and revision → DeletionReceipt; source removal and dependent access revocation follow storage policy. |
| GET `/projects/{p}/submissions/{s}/` | Read received/assessing/entry_waiting/admitted/rejected/unavailable/expired state, reason, committed entry card, nullable run_id/dataset_id and links. No run invented before admission. |
| GET `/projects/{p}/runs/{r}/` | Read RunStatus including state/stage/revision, original dataset_ids, active card/result refs, and recovery availability/reason. No percentages fabricated from model prose. |
| GET `/projects/{p}/commands/{command_id}/` | Resolve socket command receipt by stable command ID/current scope, including after a lost acknowledgment. No automatic redispatch. |
| GET / DELETE `/projects/{p}/runs/{r}/result/` | Read committed Result or delete by revision. Result variants are reviewed complete/partial, Direct, and operational notice with the approved labels/references. A still-unpublished run returns 409 `result_pending`; revoked content returns 410. |
| GET `/projects/{p}/evidence/{e}/` | Read authorized typed schema/coverage, producer/lineage, source snapshots and governed artifact/code refs. Recheck owning Chat context; no cross-Chat analytical retrieval. |
| GET `/projects/{p}/evidence/{e}/rows/` | Bounded cursor over the immutable typed table and locators; supports column/row selection only within permitted schema/coverage. Preview is not a new computation. |
| GET `/projects/{p}/artifacts/{a}/content/` | Governed verified byte stream after current access checks. Never a direct volume URL; raw uploads are not implicitly exposed by this route. |
| GET `/projects/{p}/deletions/{x}/` | Read accepted/reconciling/retirement_pending/complete/blocked cleanup disposition without retaining deleted content in diagnostics. The associated content is already revoked. |

User text submission, entry/analytical replies and recovery primarily use the socket commands below; no second write path with separate semantics is introduced. HTTP status/snapshot/command lookup supports reconnect and developer exercise. A later transport alias must call the same command service and share identity keys.

## WebSocket admission and command protocol

Browser WebSocket construction does not provide arbitrary custom request headers. Do not require `X-Querivue-Client` or an ordinary HTTP CSRF header on the Upgrade. Before accepting the socket, enforce explicit allowed browser Origin (scheme/host/port), Host and live Project/Chat scope; reject missing, null or foreign browser origins rather than relying on DEBUG's permissive defaults. Mint a finite-lived single-use opaque connection ticket through the CSRF-protected HTTP endpoint, bound to this Project/Chat, origin and local operator context. Store only its verification hash; keep it out of URLs, browser persistent storage, request logs and trace payloads.

Select subprotocol `querivue.chat.v1`. First frame is `{type:"hello",ticket,after_sequence:null|integer}`. Consume/validate the ticket atomically before joining groups or sending any content. Until then accept only that frame under finite connection/frame/time caps; any other traffic closes the socket. Reconnection mints a new ticket. Host/Origin checks and the ticket supplement the local trust boundary; none creates multiuser authentication. Recheck Chat/Project lifecycle on every command and outbound content fetch, not only at connect.

Command frame: `{type:"command",command_id:<uuid>,idempotency_key:<uuid>,command:<enum>,expected_revision:<integer|null>,payload:<typed object>}`. The socket path supplies Project/Chat scope; conflicting payload scope fields are rejected. A committed command yields `{type:"command_receipt",command_id,receipt_id,resource_ref,state}`; an error yields `{type:"command_error",command_id,error:<same public error schema>}`. A socket receipt means the database command committed, not that entry accepted it or analysis completed. Duplicates return the same receipt; changed payload under a key is a conflict. Exact final response schemas are versioned with this protocol.

| Command | Payload and effect |
| --- | --- |
| `submit_question` | `{text,dataset_ids:null|[uuid],reply_to_result_id:null|uuid}`. Record exact new message, received conversational cutoff and explicit target. Null means default eligible sources; supplied source IDs must be unique, live and in this Project. Ready snapshot admission and current guards remain authoritative. Return SubmissionReceipt. |
| `reply_entry` | `{submission_id,question_id,text,suggestion_id:null|uuid}`. Target the exact original entry-policy wait; preserve original receipt/basis and finite chain limits. A suggestion is not a default selection or user text replacement. Return that chain's receipt. |
| `reply_clarification` | `{run_id,question_id,text,suggestion_id:null|uuid}`. Entry-screen exact linked analytical reply, claim once and resume original scope/basis. New composer text never routes here implicitly. Return linked SubmissionReceipt/resume readiness, not a new analytical run. |
| `request_recovery` | `{run_id}` plus expected run revision. Durable same-run reconciliation request, preserving all original counters/deadlines and retirement constraints. Return recovery receipt; runtime determines eligibility and next legal action. |

Control frames are `ack` with last fully applied delivery sequence, and application `heartbeat`/`heartbeat_ack` with transport state only. Unknown types/fields, binary command frames, oversized messages and unauthorized scopes receive bounded errors/closure. Ping/liveness, reconnect backoff, ticket lifetime, queue/frame caps and client connection limits are finite configuration gates; no unmeasured numerical defaults are approved here. Closing the socket does not cancel a run or release its domain accounting as if work stopped.

## Streaming, ordering and reconnect

Use durable per-Chat delivery identities/cursors in the existing delivery-record family. **Delivery sequence is distinct from ChatVisibility's semantic sequence/cutoff.** Progress, heartbeat and answer fragments do not silently change a received question's conversational basis. Heartbeats are not durable content events. Domain transition IDs deduplicate visible-event creation; each socket tracks its own cursor, so one tab's acknowledgment cannot consume another tab's history.

Public durable event envelope: `{type:"event",event_id,sequence,kind,resource_ref,resource_revision,payload}`. Event kinds cover received/admitted/rejected submission, sanitized run stage/state, committed entry/analytical card, committed publication and revocation. Stage events come from runtime transitions, never private reasoning text. Notification payloads over the Channels layer contain bounded identifiers/revisions, not copied answer/source bytes. The consumer re-reads authorized canonical state before delivery. Redis is a wake-up channel, not the event ledger or run authority.

On connect, establish notification subscription, then read a consistent authorized snapshot/replay watermark; query durable events through that watermark, drain newer events and continue live. Use cursor/reread loops to avoid a subscribe-versus-snapshot gap. A bounded server-side watermark reconciliation catches lost notifications even when no later event arrives; this is not browser Chat polling. Replay reauthorizes current state: an old queued publication that is now revoked becomes a revocation/suppressed non-content disposition, never replayed deleted text. A missing/too-old/incompatible cursor yields `resync_required` plus a fresh authorized snapshot; acknowledgments alone never delete authoritative records.

The socket streams live progress while analysis runs. Answer text becomes streamable only after the exact reviewed/Direct/notice publication is committed. For incremental display, emit `publication_start`, ordered `publication_chunk` frames and `publication_end` for that immutable event, binding event_id, publication_id, content_hash and chunk ordinal. The renderer creates chunks from the already committed public representation; it does not regenerate text, split typed value/citation atoms into altered claims or treat network fragments as new publications. Chunk replay references the same identity/bytes. A client advances its delivery cursor only after completing the event or receiving an explicit terminal revoked/aborted disposition. Duplicate frames cannot append duplicate paragraphs/cards.

Recheck access between bounded chunks. Revocation aborts further publication chunks, clears affected visible content and records that event's revoked disposition before delivering later events. Already delivered/buffered bytes cannot be recalled. Reconnect after a partial stream either resumes the same verified representation or replaces it with its authorized full snapshot/revoked state; never run the model to finish a transport stream. Raw model token streaming and unapproved draft streaming would conflict with existing publication gates and are not introduced by the WebSocket request.

Bound send queues and outstanding command work. Coalesce only replaceable stage notifications whose current state is available; never silently discard a card, publication or revocation. A slow client gets resync/closure rather than unbounded buffering. Channels group delivery can drop messages, so broker acknowledgment is not client delivery proof. Runtime/worker execution does not depend on a browser acknowledgment. Disconnect, Redis notification outage or consumer restart must not re-admit work, refill budgets or change run identity.

## Public states, files and service handoff

Submission and run are separate resources. Public run states are queued/running/waiting_for_clarification/interrupted/completed/failed/source_unavailable/expired; `stage` and `revision` refine progress without exposing model internals. Completed analytical Result carries complete/partial and reviewed/direct labels separately. Interrupted means recoverable operational work with no terminal publication; availability is rechecked on click. A terminal publication, removed source, exhausted limits or hard expiry cannot be reopened by request_recovery. Successful action outcomes remain reused under the existing runtime contract. A new analysis is a separate explicit submission.

Transfers reserve the declared raw byte quota before writing, stream with bounded limits, verify exact size/hash and retain failed admitted uploads under deletion policy. Ingestion screening and preparation operate after transport storage; full files never enter semantic model input. Confirmations bind exact preview/settings revision. A replacement that lost its original source conflicts rather than becoming an Add. No partly selected snapshot is exposed.

Artifact content uses an approved media allowlist, `X-Content-Type-Options: nosniff` and safe Content-Disposition. PNG may display inline; recorded executed SQL/Python is escaped plain text. No arbitrary uploaded HTML/SVG execution or user filename-derived path. Initial API does not support Range/conditional cached bodies: reject Range with a documented 400 `range_not_supported`; clients may make a complete new authorized request. Verify immutable bytes before exposing them; check revocation during bounded reads without holding locks for the stream. Deletion returns the stable revocation/cleanup receipt (202 while cleanup is pending, 200 on repeated completed receipt), not a promise bytes/processes disappeared immediately.

Both HTTP and socket handlers call the same typed application command/query services and approved Postgres adapter. Commit state plus durable replay/delivery intention before returning success; no background thread in a view/consumer is the job authority. Phase 4 selects the worker/broker transport, consumes durable intents with at-least-once idempotent processing and wakes socket consumers after authoritative transitions. Redis job, checkpoint and socket namespaces/accounting stay distinct. Socket disconnect never closes the worker's run, and no consumer holds coordinator ownership or long database transactions merely to keep a connection open.

## Acceptance and remaining gates

- Boundary/schema: all endpoints and command/event/result variants have strict generated schemas/examples; malformed/unknown inputs and mixed ownership fail consistently; no secrets, private drafts or raw source/model payloads leak through errors/logs.
- Browser/local access: genuine allowed UI connects; foreign/null/missing origins, invalid Host, missing CSRF/application header, forged/reused/expired/wrong-Chat tickets and pre-hello commands fail. Verify the actual development Upgrade proxy and loopback binding; CSRF is not claimed to authenticate arbitrary local processes.
- Durable transport: lost command acknowledgment, duplicate multi-tab commands, restart/reconnect at each publication chunk and subscribe/snapshot race create one message/admission/reply/publication only. Missed final Redis notification is recovered from durable state without browser polling or model calls. Slow-client bounds and cursor resync preserve revocation/card/publication semantics.
- Lifecycle: new submissions while clarification waits, racing replies, source removal during stream/replay/download, result/Chat/Project erasure, replacement conflicts, stale revision, unknown commit and interrupted recovery obey approved source/budget/time/publication invariants. A terminal run cannot become funded again through a transport path.
- Upload/evidence: concurrent quota reservations, aborted transfer, size/hash mismatch, confirmation races, typed row pagination, exact citation/code/chart rendering and full-byte download reauthorization use real storage integration. Scripted execution does not prove sandbox/model fidelity.
- Implementation owners: API phase implements route/consumer/schema/security/service adapters and browser transport tests; storage slices supply real Postgres semantics; worker/checkpoint/backend integration phases prove durable scheduling, cross-process live delivery/restart and end-to-end races. Pin compatible Django/Channels/Redis/ASGI builds and all finite transport/configuration settings before enablement. No dependency install, service, migration or live/paid call ran during this planning phase.
