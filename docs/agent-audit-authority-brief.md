## Approved invariants

- Standalone SQLite is the one transactional authority; Redis/files are projections and artifacts. Each authoritative transition uses one short `BEGIN IMMEDIATE` transaction. Do not nest LedgerOps transactions or await external effects while locked. Use canonical contract models and codec; do not weaken them or build duplicate domain schemas.
- All effects check authoritative Project/Chat/run ownership, pinned eligible sources/snapshots and tombstones, run status/deadline, current owner/generation/lease, expected attempt and applicable revision. Authority guard failures leave all changes rolled back. One active coordinator generation; takeover conditionally increments generation, renewal cannot revive a stale owner. Use finite explicit timing policy and injectable trusted clock for deterministic tests; no 2099 leases or year-based clock heuristics. Preserve original deadlines on retry/resume.
- Unique immutable identities replay the canonical receipt/outcome; same identity with changed contents is an integrity error. Every actual mutation increments run_revision. Expected queue revision remains distinct. No fake UUID hashes, invented request contents or fresh identities on replay.
- Model/dispatch/review reservations read and update durable current budget atomically. Charge once before effects; uncertain work stays reserved. Never recreate an initial budget for reservation or reset counters on retry/new process. Use canonical ModelRequest.inference.max_generated_tokens (there is no max_output_tokens field on it), exact rates/caps and unknown usage. Two run-wide review passes never become three. Do not fabricate zero cost for unknown/paid work. Duplicate reservation reuses prior identity and charge.
- Admission validates the persisted intake/assessment/target/scope/configuration/context hashes, retains exact original question and requested run identity, associates one admission per intake, and creates run plus receipt atomically. Input mismatches cannot partially create a Chat/admission/run.
- Decision validates the full strict SupervisorDecision, queue revision, keys/references, authorization, task/control exclusivity and prerequisites before replacing queue. Existing tasks preserve IDs, new tasks/actions get runtime UUIDs, mappings persist. Reject unsupported interpretation/obligation/progress semantics explicitly before any mutation rather than ignoring them. Exact replay returns original mapping. Runtime-only dispatch freezes the head and exact attempt, checks prerequisites and sets the irreversible analysis-started latch for SQL/Python before execution. No guessed future evidence.
- Implement the canonical Authority APIs already stubbed: publish_evidence, commit_preparation, finalize, delete_dataset, accept_model, record_operation, record_retirement, register_outcome, read_projection, reserve_dispatch, commit_wait, commit_review, plus repair admit/commit_decision/reserve_model/reserve_review/accept_reply/claim_run/renew_lease.
- Use EvidenceCandidate from contracts.evidence, PreparedCandidate from contracts.catalog, GraphProjection from contracts.state, and existing records/action/response models. Inspect contracts and callers to resolve exact shapes. Wire existing durable tables; adding narrow schema tables/columns/indexes for reconstructible receipts/guards is allowed with an idempotent migration for existing local ledgers. Do not discard existing state or mask incomplete operations with successful empty payloads.
- Publication requires recorded validated artifact references, exact scope/source/snapshot/operation provenance, expected generation/attempt, active candidate/review and deadline. Missing runtime proof fails closed, never trust model-carried IDs or approved boolean alone. Reviewed finalization verifies durable approval bound to exact draft/content/input/rendering identities. Direct is complete-only, pre-analysis latch, and only permitted explicit evidence/text. One terminal result per run; exact acknowledgment replay returns it. Do not publish rejected/unreviewed content.
- Deletion tombstones/revokes access first and invalidates dependent runs/results under the same transaction as publication guard. Collect deferred cleanup/retirement references; physical removal is outside transaction and requires proof. Preserve unrelated Project data.
- Operations persist immutable invocation/operation mapping before dispatch. Outcomes and collection bind exact expected attempt/generation and preserve successful siblings. Retirement proof is whole-tree/provider-confirmed, not process-kill acknowledgment. Wait/review commits precede visibility/dispatch. Accepted reply must match active wait/question/content, an actual accepted entry admission, original sources/deadline and once-only resume.
- read_projection returns the exact strict nine-field parent contract under canonical GraphProjection with ledger revisions/fence; it must not treat broad dataclass RunState as authoritative. Missing/incompatible durable records fail explicitly.
